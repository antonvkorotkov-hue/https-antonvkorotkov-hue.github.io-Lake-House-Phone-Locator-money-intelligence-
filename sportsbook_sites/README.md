# Lake House Picks + Virtual Sportsbook on Sites

This is a server-runtime adaptation of the existing `feature/private-virtual-sportsbook` GitHub branch. Existing Lake House Picks source is preserved verbatim in `lib/legacy-picks.js`; the Worker retains its routes and adds `/sportsbook` plus `/api/sportsbook/*`.

Shared accounts, invitations, sessions, accepted picks, double-entry virtual accounting and audit records use a native Sites D1 binding named `DB`. No member records or credentials live in static assets or browser storage. There is no money, payment processing or redeemable prize.

Owner setup/reset uses the Site owner's ChatGPT identity; the owner then chooses a sportsbook username/password. Friends need only an invitation code, username and password. A temporary service-only bootstrap credential is removed after acceptance tests. All browser sessions use Secure HttpOnly SameSite cookies and server-bound CSRF tokens. Passwords use scrypt with random salts, N=32768, r=8 and p=3 (32 MB working memory), adapted to the Worker runtime. Native Sites visitor identity and sportsbook participant identity remain separate.

`SB_OWNER_EMAIL`, `SB_SETUP_SECRET` (temporary), `SB_ODDS_AUTHORIZED` and `SB_LIVE_ODDS_AUTHORIZED` are private Site runtime variables. Existing `ODDS_API_IO_KEY` and `BETSTACK_API_KEY` are preserved; no key values are included in source. API keys' presence is not a legal audit of a provider agreement. Data use must stay within the owner's existing subscription rights.

ESPN supplies actual event identity, score, clock and status. Only exact home/away and near-exact kickoff matches are associated with the existing Odds-API.io book feed. Market-level source timestamps are required; old event-wide timestamps and reserve prices never authorize a wager. Missing/suspended prices, invalid clocks, expired quotes and closed markets fail closed. Pregame prices expire after 120 seconds; in-play prices after 15 seconds. Live first-half prices close after the second period. Full game, team total, half and mapped player-stat markets import only when explicitly present. Unknown market shapes remain unavailable.

Final game settlements require agreeing scoreboard and event-summary scores from ESPN. These are two responses from one provider, not independent league verification. Partial first-half or player-stat results remain pending when not explicitly verified. Cancellation/postponement voids use published terminal status. Increasing result versions post auditable corrections. Full-game rules include overtime; exact ties push. Integer returns round down to hundredths. A negative correction creates visible member debt and blocks further spending. Grants use issuance accounting and never count as house profit. Database triggers make acceptance and ledger transfers atomic and preserve accepted terms and audit history.

Refresh is leased in D1 to limit duplicate provider calls. Feed polling and settlement currently run when authenticated visitors refresh Games; no unattended scheduled settlement is claimed. D1 is persistent across deployments. The available Sites controls do not expose a project-specific storage quota or backup-export/restore operation; no unlimited-storage or independent-backup guarantee is made. Worker memory is 128 MB per isolate. Monitor usage and platform limits before expanding the invitation group.

Checks: `python scripts/test-ledger.py`; `node scripts/test-sportsbook.mjs`; native Sites build helper. Drizzle schema-only migrations and generated metadata are checked in. Production publication uses the Sites source workflow; its source repository is a deployment mirror. The GitHub development branch remains the source of truth.
